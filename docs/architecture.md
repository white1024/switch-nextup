# Architecture

How Switch NextUp is put together, and why the parts that look odd are the way they
are. For the reverse-engineered auth and usage APIs of both providers, see
[usage-api.md](usage-api.md).

Stack: **Tauri 2** (Rust backend) + a **static HTML/JS frontend** with no bundler —
the frontend talks to Rust through `window.__TAURI__` (`withGlobalTauri`). Windows
only, for now.

## File map

```
src/                       static frontend (embedded into the binary at build time)
  index.html               markup
  main.js                  invokes backend commands; renders cards + usage bars
  styles.css               dark UI
src-tauri/
  tauri.conf.json          app config; frontendDist=../src, withGlobalTauri=true, tray
  Cargo.toml               dependencies (note the `time` pin under Gotchas)
  capabilities/default.json  window permissions
  src/
    main.rs                entry -> switch_nextup_lib::run()
    lib.rs                 Tauri commands, system tray, window-close-to-tray
    provider.rs            `Provider` enum (Claude | Chatgpt) and ONLY the operations
                           that genuinely differ per provider
    store.rs               account store, switch, capture, remove, rename, active
                           detection — provider-agnostic
    login.rs               in-app Claude OAuth login (PKCE + manual paste)
    login_codex.rs         in-app ChatGPT/Codex OAuth login (PKCE + loopback)
    usage.rs               usage fetch + parsing for both providers
  icons/                   generated by `npx tauri icon` from icon-source.png
```

## The core mechanism

Both CLIs keep the signed-in account in plain files on disk, so switching accounts is
really just swapping those files — plus the safety rules below, which are the whole
reason this is not a three-line shell script.

| | Claude Code | ChatGPT / Codex |
|---|---|---|
| live file(s) | `~/.claude/.credentials.json` **and** `~/.claude.json` → `oauthAccount` | `~/.codex/auth.json` **only** |
| identity | a separate file's `oauthAccount` object | carried **inside** the `id_token` JWT |
| stable id | `accountUuid` | `chatgpt_account_id` (= `tokens.account_id`) |
| usage API | `/api/oauth/usage` | `/backend-api/wham/usage` |
| in-app login | **paste a code** — loopback is refused | **loopback**, nothing to paste |

Each saved account lives at `~/.switch-nextup/accounts/<provider>/<name>.json` as
`{ "oauth": <credential blob>, "identity": {...} }`, with the active account pointer
in `config.json`.

### Switching

A switch overwrites the live file(s) with the chosen account's stored blob — but two
things have to happen around that, and both were learned the hard way:

1. **Fold the outgoing account's live tokens back into its stored copy first.** Both
   CLIs refresh tokens on their own schedule and the refresh token **rotates** (the
   old one dies immediately). Skip this and switching away and back reinstalls a dead
   token, logging the user out of the CLI.
2. **For Claude, write both files.** Claude Code keys the active account off the
   tokens in `.credentials.json` *and* the identity in `~/.claude.json` →
   `oauthAccount`. Writing only the tokens leaves the stored identity on the old
   account, so Claude Code keeps using — or reverts to — that account. This was the
   root cause of "the switch didn't take". Every other key in `~/.claude.json` is
   preserved.

ChatGPT needs only one file: identity travels inside the token, so there is no second
file to keep in sync. The Codex CLI and the Codex desktop app share `~/.codex`, so one
swap covers both.

All live-file writes go through `atomic_write` (temp file + rename) so a mid-write
conflict with a running CLI cannot half-switch an account.

### Token rotation

Because the live tokens rotate, the stored copy of the **active** account goes stale
between reads. Anything that needs an account's tokens for a network call must go
through `store::resolve_account_oauth(name)`, which returns the **live** tokens when
the live credentials belong to that same account (exact token match, or a stable
`accountUuid` match) and re-syncs the stored copy. A different or unidentifiable live
account falls back to the stored copy and overwrites nothing. Using the stored copy
directly is what produced a false "Session expired" on an account that was working
fine.

### Active detection

Match the live file's `refreshToken`/`accessToken` against the stored accounts. On a
mismatch — expected, since tokens rotate on refresh — fall back to the **stable
account identity** (`accountUuid`, or `chatgpt_account_id`), and re-sync the stored
copy only when that identity confirms it is the same account. A different or unsaved
live account marks nothing active and overwrites nothing.

**Never re-sync on the config pointer alone.** The pointer says which account the user
last selected, not which one is actually live; trusting it caused a data-loss bug
where one account's stored tokens were overwritten with another's.

**Active is per-provider.** One active Claude account and one active ChatGPT account
exist simultaneously — the two clients read different files, so switching one must
never disturb the other (there is a test for exactly that).

## Why the two login flows differ

The difference comes down to one thing: the `redirect_uri`.

Codex registers `http://localhost:1455/auth/callback` **with the port in it**
(fallback 1457), so the browser genuinely comes back and login is one step.

Claude Code's OAuth client uses an *ephemeral* port, and Anthropic refuses that
redirect at the moment it would issue the code — a real consent screen renders, then
"Authorization failed". So that flow pastes the code into the app instead, exactly as
the official CLI does when its own listener gets nothing. `login_begin` opens the
browser on the manual redirect and `login_submit_code` accepts `code#state`, a bare
code, or the whole callback URL. **Do not "fix" the Claude side back into a loopback.**

Identity for a Claude login comes from `/api/oauth/profile`, not the token response:
its `account.uuid` is the value stored as `oauthAccount.accountUuid`, which every
switch and every "already saved?" check keys off.

What is genuinely shared lives in one place: the PKCE helpers (`login.rs`) and
`finish_login(provider, …)` in `lib.rs`, which decides whether a completed login
matches a saved account or needs a name. `PendingLoginState` carries its `Provider` —
without that, a ChatGPT login reaching the "name this account" branch would write into
the Claude store, silently overwriting a Claude account of the same name.

Codex identity is read by base64url-decoding the `id_token` **payload only, with no
signature verification** — correct here: it is our own local file and we are not
authenticating a caller, just reading details OpenAI already put in the token.

## Storage layout

`~/.switch-nextup/`:

```
accounts/<provider>/<name>.json    { oauth: <credential blob>, identity: {...} }
accounts/<name>.json               legacy pre-multi-provider layout — read as Claude,
                                   migrated into accounts/claude/ on next write
usage/<provider>/<name>.json       cached usage (usage/<name>.json read as legacy)
config.json                        { active, active_by_provider: { claude, chatgpt } }
window.json                        last window position
```

A Claude and a ChatGPT account **may share a name** — that is what the per-provider
subdirectories are for, and it is a case worth keeping in mind when touching anything
keyed by account name.

The app was called *Claude Switch* before and kept everything in `~/.claude-switch/`.
`store::resolve_base_dir` moves that directory to `~/.switch-nextup/` once, on the
first `base_dir()` call of a process, and only when the new directory does not exist
yet, so it can never overwrite live data. If the rename fails (a file inside still
held open) it keeps using the legacy directory for that process rather than coming up
with an empty store, which would look like every saved account had been lost.

## Usage fetching

Full API details are in [usage-api.md](usage-api.md). What matters architecturally:

**The Claude usage endpoint rate-limits aggressively** — fetching two accounts
back-to-back 429s the second one even with a valid token. The primary defense is to
**only ever live-fetch the active account** (`get_usage`); non-active accounts render
last-known numbers from disk (`get_cached_usage`, no network call). Fetching idle
accounts just produced perpetual "rate limited, retrying…" notes for no benefit.

Remaining defenses for that single live call:

- a 60s frontend cache;
- a global **serial fetch queue** (`enqueueUsageFetch`, 2.5s minimum gap) that also
  paces the 429 retry timers so nothing fires back-to-back;
- a short refresh-button cooldown, so rapid re-clicks cannot stack sweeps;
- **disk-persisted last-known usage**, served flagged `stale` when a fetch fails,
  plus backoff retry.

Keep the strings "rate limited" / "429" in backend error messages — the frontend
matches on them.

Claude token refresh sends `scope` as the stored `scopes` **array joined by spaces**.
Reading it as a string sends an empty scope, the refresh returns a bad token, and
usage fails — which surfaces confusingly as "only non-active accounts error", since
the active account rarely needs our refresh (the CLI keeps it fresh).

## Tauri commands

Called from `main.js` via `invoke`. `provider` is the slug `"claude"` or `"chatgpt"`,
deserialized straight into the `Provider` enum. `list_accounts` returns **every**
provider's accounts in one call, each carrying its own `provider` field; the frontend
splits them into tabs on that field. Custom commands need no capability entry in
Tauri 2.

`list_accounts`, `switch_account{provider,name}`, `add_current_account{provider,name}`,
`remove_account{provider,name}`, `rename_account{provider,old,new}`,
`find_current_account_match{provider}`, `get_usage{provider,name}` (async live fetch —
active account only), `get_cached_usage{provider,name}` (sync, disk, no network),
`set_window_effect{effect}`, `set_compact{compact,rows}`, `check_credman_guard`,
`clear_data{scope}`, `hide_to_tray`, and the login commands (`login_begin` /
`login_submit_code` are Claude-specific; `save_pending_login` / `discard_pending_login`
serve both providers; `login_codex_account` is the one-shot ChatGPT loopback login).

`clear_data` takes `"accounts"` (saved accounts + active pointer + usage cache, all
providers) or `"all"` (the whole `~/.switch-nextup/` directory + disable autostart). It
**never touches `~/.claude/…` or `~/.codex/…`**, so it cannot sign the user out of
either CLI.

`LoginOutcome` must serialize as `"saved"` / `"need_name"` (`rename_all =
"snake_case"`) or the frontend silently treats a successful login as a new account —
there is a test asserting the wire tags, because `cargo test` and `node --check` can
both be green while an IPC boundary is broken.

The backend emits an `accounts-changed` event after mutations so the UI reloads.

**System tray**: accounts are listed in one labelled section per provider, separated
by a menu separator — a flat list would show two active markers at once, since each
provider has its own active account. Menu ids are provider-qualified
(`switch::<slug>::<name>`) so accounts sharing a name cannot collide. Plus Open/Quit
and a "Start with Windows" checkbox (run-at-login via `tauri-plugin-autostart`,
toggled entirely in Rust). A login-triggered launch passes `--minimized` so `setup()`
skips showing the window and the app starts hidden in the tray.

**Single instance** (`tauri-plugin-single-instance`, registered as the **first**
plugin in `run()`): launching the executable again while a copy is running hands its
args to the running instance, which just shows its window, and exits. Without this,
two instances fought over the same tray icon and independently overwrote the same
files; a second copy could even come up with a blank webview from sharing the first's
WebView2 user-data folder.

## Window UI

A **frameless, transparent, fixed-size** widget (`decorations:false`,
`transparent:true`, `resizable:false`). It starts `visible:false` and is shown by
`setup()` after its saved position is restored, so it never flashes at the default
spot first. Layout is flex-column: fixed titlebar, scrolling account list, fixed
footer.

- **Position persistence** — the top-left position is saved to `window.json` on every
  close path and restored before the window is shown. Only position is persisted (the
  window is fixed-size).
- **Custom titlebar** — `data-tauri-drag-region` for dragging. Buttons: pin
  always-on-top, backdrop toggle, refresh, compact-bar toggle, and a close button that
  **hides to the tray rather than quitting** (minimize was intentionally removed).
- **Claude / ChatGPT tabs** — the account list and footer are scoped to one provider
  at a time; the choice persists in `localStorage`. Usage refresh and the usage cache
  run per-provider independently, and the cache is keyed by provider **and** name,
  since the two providers may have accounts of the same name.
- **Compact strip** — one row per provider that currently has an active account (so
  0, 1, or 2 rows), each tagged with a provider label before the account name. The
  native window height scales with the row count and is resized live when that count
  changes.
- **Account cards** — one control doubles as the active indicator: a clickable
  outline **Switch** button on non-active cards, or a filled, disabled **Active**
  button on the current one.
- **Stale usage must not read as live** — a rate-limit bucket is dropped from both the
  full meter and the compact strip once its `resets_at` is more than 5 minutes past:
  its cached percentage describes the *previous* window. Without this, a nine-day-old
  cache rendered "Current session · resets now". The grace period preserves a genuine
  just-after-reset reading. Credit and spend buckets are exempt — they have a fixed
  expiry rather than a rolling window, told apart by `limit_dollars != null`.
- **In-app modal** replaces native `prompt()`/`confirm()` so dialogs match the theme.
  Every "would this overwrite an existing account?" check must be scoped to the same
  provider, and must treat a legacy account with no `provider` field as Claude.
- **Backdrop effects** — the backdrop button cycles: modern DWM `SystemBackdrop`
  (`acrylic`, `mica` — Windows 11 22H2+, system-controlled tint), legacy
  `AccentPolicy` (`legacy-acrylic`, `blur` — Windows 10+, custom tint), and `none`
  (solid). The five-way cycle and its titlebar label are scaffolding for comparing
  implementations; once a final backdrop is chosen the unused arms can be trimmed.

Acrylic is inherently variable: DWM and legacy acrylic sample the desktop behind the
window and dim when the window is inactive, by design. Re-applying cannot make it
constant — consistency only comes from opacity.

## Build / run

```sh
npm install        # installs @tauri-apps/cli
npm run dev        # hot-reload dev window
npm run build      # release installer -> src-tauri/target/release/bundle/nsis/
```

Rust-only check: `cd src-tauri && cargo build`. Tests: `cargo test`.

`bundle.targets` is `["nsis"]` with `installMode: currentUser`, so the build produces
a per-user, unsigned installer (no UAC to install; SmartScreen warns about an unknown
publisher until code-signed).

## Gotchas

- **A frontend edit needs a rebuild before you launch the executable.** `src/` is
  embedded into the binary at build time — only `npm run dev` serves it live — so
  launching an already-built binary after editing `main.js` / `index.html` /
  `styles.css` silently shows the **old** UI.
- **Dependency pin**: `time` is pinned to **0.3.51** in `Cargo.lock` (0.3.52 breaks
  `cookie 0.18.1`, a transitive dependency). If a fresh `cargo update` reintroduces
  the `cookie` build error (`format.parse takes 2 arguments`), re-run
  `cargo update -p time --precise 0.3.51`.
- **Switching works without closing Claude Code** — the file swap takes effect live,
  with no restart or editor reload. The same is plausible for Codex, which reads
  `auth.json` the same way, but it has not been explicitly verified.
- **Windows credential source**: swapping `.credentials.json` only affects Claude Code
  while the `tengu_windows_credman` flag is off. If it is on, Claude Code reads
  Windows Credential Manager and file-swapping silently stops working.
  `store::credman_guard_active()` detects this (via an env override and the cached
  feature flag in `~/.claude.json`) and the UI shows a warning banner — but it only
  warns; it does not yet write to Credential Manager.
- **Backdrop linking**: the HWND comes from `raw-window-handle`, with raw FFI to DWM
  and user32. `SetWindowCompositionAttribute` is an **undocumented user32 export
  absent from user32.lib** — static linking fails with `LNK2019`, so it is resolved at
  runtime via `GetProcAddress`. Do not switch it back to a `#[link]` import.
- **Secrets**: `~/.switch-nextup/` holds plaintext OAuth tokens, exactly as
  `~/.claude/` and `~/.codex/` do. Never print or log token values; treat the folder
  as sensitive.
- The frontend uses the global `window.__TAURI__` API with no npm frontend
  dependencies. Keep it that way unless introducing a bundler deliberately.
